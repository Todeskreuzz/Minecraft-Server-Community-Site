# Community Forum Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline execution.

**Goal:** Replace the landing page with a real community forum, joining/download guidance and an owner-only server overview.
**Architecture:** GitHub Pages serves static files. Supabase Auth authenticates members; Postgres RLS enforces permissions. Falix is the planned Minecraft host, not yet provisioned.
**Tech Stack:** HTML, CSS, browser JavaScript, Supabase REST/Auth and SQL. No paid services or new dependencies.
**Spec:** User-approved conversation: GitHub Pages temporarily, Supabase Free, accounts/topics/replies, private owner tab. Existing DE/EN support retained.

## Global Constraints
- Only Todeskreuzz/Minecraft-Server-Community-Site; no changes to Minecraft server files.
- No invented server address, player profiles, discussions, download or live metrics.
- Browser may contain publishable key only. No passwords or privileged API keys in repository.
- Admin authorization enforced by database, never by tab visibility.
- Existing ZIP and offline UID tooling preserved.

## Review Focus
- HTML/script injection in member content: render user text with textContent.
- Unauthenticated and non-owner writes: explicit grants plus RLS; no client role promotion.
- Missing Supabase schema/network: actionable message, never fabricated discussions.
- Expired session: refresh tokens, clear failed session, require sign-in again.
- Unknown Falix details: explicit unconfigured state and direct provider-panel link, no fake telemetry.
